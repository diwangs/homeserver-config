# Radicale (`dav`)

> Hostnames below use `example.org` for the hosting zone (`vault_public_domain`).

[Radicale](https://radicale.org/) CalDAV/CardDAV server on LXC 111 in the dmz, public as
`dav.us.example.org` through the BunkerWeb edge (`roles/tenant/bunkerweb`). It replaces the
contacts and calendars that lived in Nextcloud.

| | |
|---|---|
| vmid / hostname | 111 / `dav` (unprivileged, `nesting=1`) |
| dmz address | `fd5a:715f:1edc:a706::2c` (pinned DHCPv6 lease `host_dav`); IPv6 only |
| Guest OS | NixOS; the upstream image `ghcr.io/kozea/radicale:<dav_version>` runs under `virtualisation.oci-containers` (the seafile pattern) |
| Origin | plain HTTP :80, admitted from the edge's ULA only (nixos-fw) |
| Auth | htpasswd, bcrypt, one user (`vault_dav_htpasswd`); `rights = owner_only` |
| Data | `/mnt/frontpanel-pool/frontpanel-dataset/Radicale` -> `/mnt/radicale` (mp0), owned by host uid 101000 |

## Layout

Same architecture as `roles/tenant/seafile`: the flake in `files/nixos/` *is* the image,
`tasks/build_template.yml` builds it on the workstation, `tasks/nixos.yml` runs
`nixos-rebuild switch` in the guest. `site.nix` (rendered, gitignored) holds the hostname, the
edge address and the image tag — no secrets.

Radicale listens on IPv4 only inside the container and Docker cannot hand an IPv6 publish to
it, so the container is published on `127.0.0.1:5232` and a host nginx **stream** relay serves
`[::]:80` (as in seafile). The image runs as uid 1000, hence the dataset owner `101000`
(unprivileged CT offset 100000). The container is read-only with all capabilities dropped; the
config is generated by Nix and holds nothing secret.

## Secret

`vault_dav_htpasswd` in `group_vars/all/vault.yml`: one line, `user:$2y$...`.

```
htpasswd -nbB <user> '<password>'     # or: nix shell nixpkgs#apacheHttpd -c htpasswd -nbB ...
ansible-vault edit group_vars/all/vault.yml
```

It is rendered to `/var/lib/dav/secrets/users` (root dir 0700) and bind-mounted read-only.
The unit skips itself until that file exists. Changing the vault entry restarts the container.

## First run

1. Cloudflare: create `dav.us.example.org` as a CNAME to `edge.us.example.org` (DNS only).
   The wildcard certificate already covers it.
2. `ansible-playbook playbooks/configure.yml --limit prydwen` (DHCP lease `host_dav`).
3. `ansible-playbook playbooks/init_proxmox.yml --limit sentinel-lp` (creates CT111), then
   `ansible-playbook playbooks/configure.yml --limit sentinel-lp,dav,bunkerweb`.

Verify from outside the house:

- `curl -i -X PROPFIND -H 'Depth: 0' https://dav.us.example.org/` -> `401`; with `-u user:pass`
  -> `207`, over IPv4 and IPv6.
- The origin refuses direct access: port 80 on the guest's GUA/ULA from anything but the edge.
- A client (DAVx5, iOS, Thunderbird) given the base URL `https://dav.us.example.org/<user>/`
  discovers its collections. `/.well-known/{caldav,carddav}` is **not** redirected by the edge;
  give clients the full URL (DAVx5 and Thunderbird accept it).

## Migrating from Nextcloud

`files/migrate_from_nextcloud.sh` needs no login on either side. Run on the Proxmox host (it uses
`pct`), it reads one user's raw vCards and calendar objects from Nextcloud's Postgres (CT103; the
Nextcloud 35 `occ` has no export command) and writes them into Radicale's storage on the ZFS
dataset, owned by host uid 101000:

```
ssh root@sentinel-lp 'DRY_RUN=1 bash -s -- <nextcloud-user> <radicale-user>' \
  < roles/tenant/dav/files/migrate_from_nextcloud.sh      # list what would be copied
ssh root@sentinel-lp 'bash -s -- <nextcloud-user> <radicale-user>' \
  < roles/tenant/dav/files/migrate_from_nextcloud.sh
```

Each collection is staged and renamed into place; an existing destination collection is skipped
(`FORCE=1` moves it aside and replaces it). Skipped: the generated `contact_birthdays` calendar,
subscriptions, trashed calendars and the system address book. Nothing in Nextcloud is changed.
Done once for `diwangs` (34 contacts, 1 event); Nextcloud's `admin` account was left out on purpose.

Afterwards log in with a client (or `curl -u user -X PROPFIND -H 'Depth: 1'
https://dav.us.example.org/<user>/`) to confirm the collections show up, repoint clients, and leave
Nextcloud's data alone until the new setup has run for a while.

## Backup

The collections are plain files (one `.vcf`/`.ics` per item) on the encrypted RAID-Z pool; there
is no separate backup job. Take a ZFS snapshot of the `Radicale` directory's dataset, or copy
`/mnt/frontpanel-pool/frontpanel-dataset/Radicale/collections` before an upgrade.

## Upgrading

Bump `dav_version` (`defaults/main.yml`) after reading the Radicale release notes and diffing
upstream's Dockerfile (user, VOLUME, CMD) against `files/nixos/configuration.nix`, then rerun
`playbooks/configure.yml --limit dav`.

## Tests

`python3 -m unittest discover -s roles/tenant/dav/tests` evaluates the flake with a placeholder
`site.nix` (skipped without Nix).
